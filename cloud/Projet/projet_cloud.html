🎯 Objectifs du projet

  • Déployer une architecture 3-Tiers complète (Passerelle + Web + Base de données)
  • Segmenter le réseau en zones DMZ (192.168.100.0/24) et LAN (192.168.10.0/24)
  • Configurer un firewall iptables sur la passerelle (VM-GW)
  • Automatiser l'ensemble du déploiement avec GitHub Actions (approche GitOps)

🎯 Pourquoi avoir choisi GitOps ?

  • Automatisation totale : Un simple git push déclenche tout le déploiement
  • Traçabilité : Chaque modification est versionnée et auditable
  • Reproductibilité : L'infrastructure peut être recréée à l'identique en quelques minutes
  • Rollback facile : Revenir à une version antérieure via git revert
  • Collaboration : Plusieurs personnes peuvent travailler sur l'infrastructure via des branches Git

Automatisation

CI/CD Pipeline

Le workflow GitHub Actions se déclenche automatiquement à chaque git push sur la branche main.

📋 Étapes du workflow :

1
Checkout
Récupération du code source depuis GitHub
2
Installation des outils
Installation de oc (OpenShift CLI) et virtctl (KubeVirt)
3
Authentification OpenShift
Connexion au cluster via les secrets GitHub OPENSHIFT_SERVER et OPENSHIFT_TOKEN
4
Déploiement des VMs
oc apply -f vms/vm-gw.yaml et oc apply -f vms/vm-web.yaml
5
Déploiement MySQL
oc apply -f mysql-deployment.yaml (Pod base de données)
6
Démarrage des VMs
virtctl start vm-gw -n ganafaye-dev et virtctl start vm-web -n ganafaye-dev
✓
Vérification finale
Contrôle de l'état des VMs (oc get vmi) et des pods (oc get pods)

🔐 Secrets GitHub configurés

OPENSHIFT_SERVER OPENSHIFT_TOKEN

Ces secrets permettent l'authentification sécurisée avec le cluster OpenShift sans exposer de données sensibles.
