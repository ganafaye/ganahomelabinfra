Projet 4 : Sécurité & Configuration

Gestion des Secrets et ConfigMaps (Injection Dynamique)

HARDENED SECURITY

1. Architecture de Confiance

L'objectif majeur est de supprimer tout mot de passe "en dur" dans les manifests YAML. Nous utilisons une Chaîne de Confiance où les secrets sont encodés et injectés au runtime.

Découplage des données sensibles
  • Secret : Mots de passe root (Base64).
  • ConfigMap : Noms des bases de données et paramètres non-critiques.

2. Injection via Environment Variables

Le Pod MySQL récupère ses identifiants de manière sécurisée sans que l'administrateur ne puisse les lire en clair dans le Deployment.

env:
- name: MYSQL_ROOT_PASSWORD
  valueFrom:
    secretKeyRef:
      name: mysql-pass-si
      key: root_password

3. Validation de l'encodage

Vérification de l'encodage Base64 via le CLI Kubectl :

kubectl get secret mysql-pass-si -o yaml

Résultat : YWRtaW4= (Valeur hachée de 'admin')
