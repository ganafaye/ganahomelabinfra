Projet 3 : Architecture Multi-tiers (App + SGBD)

Isolation réseau et Persistance des données sur Kubernetes

N-TIERS ARCHITECTURE

1. Présentation du Système

Séparation de la couche de présentation (Adminer) et de la couche de données (MySQL). L'objectif est de garantir qu'une faille sur le Web n'expose pas directement le serveur de données.

Découverte de Service (DNS)

Le Frontend utilise le nom DNS interne mysql-service pour contacter la base de données. Kubernetes gère la résolution d'IP automatiquement.

2. Gestion de la Persistance (PVC)

Pour éviter la perte de données (inscriptions, inventaires), nous avons implémenté un PersistentVolumeClaim.

# Extrait du PVC
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pv-claim
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 2Gi

Le volume est monté sur /var/lib/mysql dans le conteneur.
